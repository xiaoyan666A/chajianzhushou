# 历史记录长按删除 · 设计文档

日期：2026-08-04
项目：查件助手（com.chajianzhushou.app）
状态：已获用户确认（交互/视觉/存储边界）

## 背景与目标

查件页输入框下方的"最近查询"悬浮面板由横向圆角 chip 组成，目前每个 chip 只有"点击回填输入框并自动查询"一种交互。本次为历史记录项增加长按删除能力。

## 需求（与用户逐项确认）

1. 长按任意历史 chip 进入"删除待命"态。
2. 只有被长按的那张 chip 出现"×"删除按钮，其余 chip 保持正常、照常点击查询。
3. 点击"×"删除该条记录，Toast 提示"已删除"，无确认框；面板保持展开，该 chip 立即消失。
4. 待命态下点击 chip 本体（非"×"）取消待命，不触发查询。
5. 长按另一张 chip 时，待命态切换到那张。
6. 删空后面板自动隐藏（沿用现有逻辑）。
7. 普通点击 chip 的行为不变：回填输入框、选中对应类型、自动查询。

## 交互流程

```text
长按 chip ──► 该 chip 进入删除待命（右端显示红色"×"，边框变红）
                ├─ 点"×" ──► 删除记录 → Toast"已删除" → 重渲染面板（保持展开）
                ├─ 点 chip 本体 ──► 取消待命（不查询）
                ├─ 长按另一张 chip ──► 待命切换到那张
                └─ 面板收起 / 视图销毁 ──► 待命态自动清除
```

## 视觉设计

- 每张 chip 由纯 TextView 升级为横向 LinearLayout 容器：左侧文字 TextView + 右侧"×"按钮（默认 GONE）。
- 待命态：容器边框描边改为红色（`R.color.danger`，values/ 与 values-night/ 均已存在）、"×"按钮显示；"×"为红色圆形背景 + 白色"×"字符（可复用现有圆角 drawable 或代码绘制，不新增资源文件）。
- 取消或删除后恢复原样式（边框 `hair2`、圆角半径不变）。
- 其余样式（字号、内边距、间距、横向滚动）保持不变。

## 数据与存储

- 历史记录仍存 `SharedPreferences("chajianzhushou_prefs")` 的 `query_history`（JSON 数组，元素含 `v`=值、`t`=类型）。
- 删除时按"值＋类型"精确匹配并从列表移除，写回后调用 `renderHistory()` 重渲染。
- `MAX_HISTORY=20`、`HISTORY_PANEL_MAX_ROWS=10` 不变。
- 待命态只存在于内存中，不持久化。

## 错误处理

- SharedPreferences 读写异常：沿用现有 `catch (Throwable ignore)` 风格，不崩溃。
- 删除写入失败：Toast"删除失败"，面板保持原状。
- 长按/点击回调在视图销毁后不再操作（`isViewReady` 与视图判空）。

## 实现位置

- `app/src/main/java/com/chajianzhushou/app/QueryFragment.java`
  - `renderHistory()`：chip 构建改为容器 + "×"，加 `setOnLongClickListener` 与"×"点击监听；用一个成员字段记录当前待命 chip 的"值＋类型"，重渲染前恢复。
  - 新增 `deleteQueryHistory(value, type)`：从历史列表移除匹配项、写回、返回是否删除成功。
  - 新增"取消待命"与"切换待命"辅助逻辑。
- 不新增布局/资源文件（历史面板为纯代码构建）。

## 测试要点

1. 长按 chip → 仅该 chip 出现红色"×"、边框变红。
2. 点"×" → 记录消失、Toast"已删除"、面板保持展开、其它 chip 正常。
3. 待命态点 chip 本体 → 取消待命、不触发查询。
4. 长按另一张 chip → 待命切换。
5. 删空 → 面板自动隐藏。
6. 普通点击 chip → 仍回填并自动查询。
7. 重启 App → 删除结果持久化。
8. 深色/浅色两种主题下"×"与红色边框可辨。
